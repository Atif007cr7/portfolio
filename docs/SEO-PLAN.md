### Cannibalisation decisions

- **backend vs API development vs database development:** one page (`/backend-development`). Split out only if Search Console shows separate queries landing on the wrong page.
- **web development vs web app:** `/web-development` = business websites; `/web-app-development` = software/portal intent.
- **mobile vs Flutter:** `/mobile-app-development` = the business outcome (keeps "Flutter" out of its title); `/flutter-development` = hiring intent for the technology. They link to each other.
- **AI vs business automation:** AI features on `/ai-development`; non-AI scripts, bots and schedulers on `/business-automation`.
- **payment gateway vs API integration:** separate. Payments have distinct, high-intent queries.

## 5. What only you can do (highest impact first)

The guide is explicit: *"Creating content that people find compelling and useful will likely influence your website's presence in search results more than any of the other suggestions."* The technical base is now right. What's missing is proof and first-hand content, and only you have it.

1. **Deploy this change**, then in Search Console: Sitemaps → resubmit `https://www.ansariatif.tech/sitemap.xml`; URL Inspection → `https://www.ansariatif.tech/` and 3–4 service pages → Request indexing.
2. **Public profiles → `SAME_AS`** in `scripts/build-pages.mjs` (LinkedIn, GitHub, Upwork/Fiverr…), and put `https://www.ansariatif.tech` in each profile's website field. This is the quickest way to connect your name to the site.
3. **Case studies** (`/work/<project>`) for SR Health Care, iModa, OneFoodDialer, Inventory Management: the problem, what you built, screenshots (with descriptive `alt` text), Play Store / App Store links and a verifiable outcome. Currently the site has no `<img>` at all, so it can't appear in Google Images.
4. **About page** with a real photo, background, location and how you work (who is behind the site, which Google's helpful-content guidance asks about). Then add `ProfilePage` markup and a `Person.image`.
5. **First 3 articles** from real experience (each links to its service page and back): Razorpay + Flutter + Laravel with webhooks; Flutter + Laravel/FastAPI architecture; what app development costs in India (your real ranges).
6. **Google Business Profile** as a service-area business (address hidden) if you want to appear for "app developer near me"–style searches in your city.
7. **Bing Webmaster Tools** → "Import from Google Search Console" (5 minutes, covers Bing, DuckDuckGo and Yahoo).
8. **Promote** (the guide's "Promote your website"): share each case study/article on LinkedIn, relevant communities and with past clients. If client sites credit you, use a plain brand link (`Built by Atif`). Keyword-rich footer links spread across many sites are link spam.

## 8. How pages are built

- `index.html` is hand-written, except two generated regions: the footer service links (`<!-- services-links -->`) and the structured data (`<!-- schema -->`).
- Service pages, `404.html`, `sitemap.xml` and `robots.txt` are generated:
  ```bash
  node scripts/build-pages.mjs
  ```
  - Content lives in `content/services.mjs`, one object per page. In `intro` paragraphs, `[link text](/slug)` becomes an internal link (unknown slugs fail the build).
  - Site identity (`SITE`, `NAME`, `ALT_NAMES`, `SAME_AS`, `KNOWS_ABOUT`) lives at the top of `scripts/build-pages.mjs`.
  - The build fails on duplicate titles/descriptions/H1s, a wrong homepage canonical, or any URL on a non-canonical host.
  - If you change the homepage FAQ, re-run the build so the `FAQPage` markup matches.
- Generated files are committed, so Vercel needs no build step.

## 9. Search Console routine

- **After each deploy that changes URLs or titles:** resubmit the sitemap; inspect and request indexing for the changed pages.
- **Weekly (first 2 months):** Pages report (indexed vs "Discovered/Crawled – currently not indexed"), Performance → Queries.
- **Monthly:**
  - pages with impressions but CTR < 2% → rewrite title/description;
  - queries at positions 8–20 → expand that page with the specific answer searchers want;
  - queries that land on the wrong page → adjust copy/links (see cannibalisation decisions).
- **Expect:** brand searches ("Ansari Mohd Atif", "ansariatif") first, within days to weeks. Long-tail service + technology queries (e.g. "Flutter Razorpay integration", "Flutter developer with Laravel backend") come over months, as content and links grow. Broad terms like "website development" are dominated by marketplaces and agencies and need substantial content and links. Nobody can guarantee #1.
